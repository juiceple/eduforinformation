### 1-2. 소프트웨어 V모델

폭포수 모델에 **테스트 단계를 짝지어** 강조한 모델. 왼쪽(개발)과 오른쪽(테스트)이 V자로 대응한다.

```
 사용자 요구사항 ─────────────────────────── 인수 테스트
       분석 ───────────────────────── 시스템 테스트
          설계 ─────────────────── 통합 테스트
             구현(코딩) ─────── 단위 테스트
                     ╲       ╱
                       ╲   ╱
                        ╲╱
```

| 개발 단계 | 짝이 되는 테스트 | 무엇을 확인하나 [보충] |
| --- | --- | --- |
| 사용자 요구사항 | **인수 테스트** | 사용자 요구를 만족하는가 (알파·베타 테스트) |
| 분석 | **시스템 테스트** | 시스템 전체가 기능·비기능 요구사항을 만족하는가 |
| 설계 | **통합 테스트** | 모듈 간 **인터페이스**가 잘 맞는가 |
| 구현 | **단위 테스트** | 모듈 하나가 제대로 동작하는가 |

> 순서 암기: **요·분·설·구 → 단·통·시·인** ("단통 시인")
> [보충] 검증(Verification): 제품을 **올바르게** 만들었나(명세 기준) / 확인(Validation): **올바른 제품**을 만들었나(사용자 기준)

## 2. 애플리케이션 테스트

### 2-1. 통합 테스트 [보충]

단위 테스트를 마친 모듈들을 결합하면서 **인터페이스 결함**을 찾는 테스트

| 방식 | 설명 | 필요한 가상 모듈 |
| --- | --- | --- |
| 하향식(Top-down) | **상위 모듈부터** 하위로 통합 (깊이 우선 / 너비 우선) | **스텁(Stub)**: 아직 없는 **하위** 모듈 대신 |
| 상향식(Bottom-up) | **하위 모듈부터** 클러스터로 묶어 상위로 통합 | **드라이버(Driver)**: 아직 없는 **상위** 모듈 대신 호출 |
| 빅뱅 | 모든 모듈을 한꺼번에 통합 | 없음 (결함 위치 찾기 어려움) |
| 샌드위치(혼합식) | 상위는 하향식, 하위는 상향식 | 스텁 + 드라이버 |

> 암기: **하향식 = 스텁, 상향식 = 드라이버** ("위에서 내려오면 아래가 없어서 스텁")

### 2-2. 테스트 커버리지

| 종류 | 설명 |
| --- | --- |
| 기능 기반 커버리지 | 애플리케이션의 **모든 기능**을 100% 목표로 두고, 실제 테스트한 **기능 수**를 측정 |
| 라인 커버리지 | 전체 소스 코드 **라인 수** 중 테스트 시나리오가 수행한 **라인 수**를 측정 |
| 코드 커버리지 | 소스 코드의 구문·조건 등 **구조**가 얼마나 테스트되었는지 측정 (아래 6종) |

### 2-3. 코드 커버리지 6종

| 커버리지 | 기준 |
| --- | --- |
| 구문(Statement) | 모든 **명령문**을 적어도 한 번 수행 |
| 결정(Decision, 분기) | 각 **결정문 전체** 결과가 적어도 한 번씩 **참·거짓** |
| 조건(Condition) | 결정문 안의 **각 개별 조건**이 적어도 한 번씩 참·거짓 |
| 조건/결정 | 전체 조건식도 참·거짓, **개별 조건식도** 참·거짓 (위 두 개의 최소 조합) |
| 변경 조건/결정(MC/DC) | 각 개별 조건이 **다른 조건과 무관하게 독립적으로** 전체 결과에 영향을 주는지 확인 |
| 다중 조건 | 개별 조건식의 **모든 가능한 조합**을 테스트 |

**[보충] 예제**: `if (A && B)`

| 커버리지 | 필요한 테스트 케이스 (A, B → 결과) | 개수 |
| --- | --- | --- |
| 결정 | (T,T → T), (F,T → F) | 2 |
| 조건 | (T,F → F), (F,T → F) ← 각 조건은 참·거짓 다 나오지만 **결과가 둘 다 거짓** → 결정 커버리지는 불만족! | 2 |
| 조건/결정 | (T,T → T), (F,F → F) | 2 |
| MC/DC | (T,T → T), (F,T → F), (T,F → F) — A만 바꿔도, B만 바꿔도 결과가 바뀜 | 3 |
| 다중 조건 | (T,T), (T,F), (F,T), (F,F) — 조건 n개면 **2ⁿ개** | 4 |

> 함정: **조건 커버리지를 만족해도 결정 커버리지를 만족하지 못할 수 있다.**

### 2-4. 블랙박스 vs 화이트박스 테스트

| 구분 | 블랙박스 테스트 | 화이트박스 테스트 |
| --- | --- | --- |
| 관점 | **명세서·요구사항**에 나타난 **기능**이 완전히 작동하는지 | 코드 **내부 구조**, **논리적인 모든 경로** |
| 다른 이름 | 기능(명세 기반) 테스트 | 구조(코드 기반) 테스트 |
| 기법 | 동치 분할, 경계값 분석, 원인-효과 그래프, 오류 예측, 비교 | 기초 경로, 루프, 조건, 데이터 흐름 |

**블랙박스 기법** [보충 설명]

| 기법 | 설명 |
| --- | --- |
| 동치 분할(Equivalence Partitioning) | 입력값을 **같은 결과가 나오는 그룹**으로 나눠 대표값만 테스트 (예: 점수 0~59 / 60~100) |
| 경계값 분석(Boundary Value) | 오류가 많은 **경계 근처**(경계, ±1)를 테스트 (예: 59, 60, 100, 101) |
| 원인-효과 그래프(Cause-Effect) | 입력(원인)과 출력(효과)의 관계를 그래프·**의사결정 테이블**로 분석 |
| 오류 예측(Error Guessing) | 테스터의 **경험과 감각**으로 오류가 날 만한 곳을 테스트 |
| 비교(Comparison) | 같은 입력을 **여러 버전**의 프로그램에 넣어 결과 비교 |

**화이트박스 기법** [보충 설명]

| 기법 | 설명 |
| --- | --- |
| 기초 경로(Basis Path) | 맥케이브의 **순환 복잡도**로 독립 경로 수를 구해 모두 테스트 — V(G) = E − N + 2 (간선 − 노드 + 2) = 조건 수 + 1 |
| 루프 검사 | 반복문 구조(단순·중첩·연결 루프)에 집중 |
| 조건 검사 | 프로그램 모듈 안의 **논리적 조건**을 테스트 |
| 데이터 흐름 검사 | 변수의 **정의와 사용 위치**를 따라 테스트 |

### 2-5. [보충] 소프트웨어 테스트 7원리

| 원리 | 설명 |
| --- | --- |
| 결함 존재 증명 | 테스트는 결함이 **있음**을 보여줄 뿐, **없음**을 증명할 수 없다 |
| 완벽한 테스트 불가능 | 모든 경우를 다 테스트할 수는 없다 |
| 초기 집중 | 개발 **초기**에 테스트를 시작해야 비용이 적다 |
| 결함 집중 | 결함은 **일부 모듈에 몰려** 있다 (**파레토 법칙** 80:20) |
| 살충제 패러독스 | 같은 테스트를 반복하면 새 결함을 못 찾는다 → 케이스를 계속 개선 |
| 정황(상황) 의존 | 소프트웨어 성격에 따라 테스트 방법이 달라진다 |
| **오류-부재의 궤변** | 결함이 없어도 **사용자 요구사항을 충족하지 못하면** 품질이 높다고 볼 수 없다 |

## 3. 자료구조

| 구조 | 원리 | 설명 |
| --- | --- | --- |
| 스택(Stack) | **LIFO** (후입선출) | **한쪽 끝**에서만 삽입(Push)·삭제(Pop). TOP 포인터 하나 |
| 큐(Queue) | **FIFO** (선입선출) | **한쪽 끝(Rear)** 에서 삽입, **반대쪽(Front)** 에서 삭제 |
| [보충] 데크(Deque) | 양쪽 | **양쪽 끝**에서 모두 삽입·삭제 |

**[보충] 활용**
- 스택: 함수 호출(복귀 주소), 재귀, 후위 표기식 계산, 되돌리기(Undo), 괄호 검사
- 큐: 프로세스 스케줄링(준비 큐), 프린터 스풀, 버퍼

**[보충] 예제**: 빈 스택에 `PUSH A, PUSH B, POP, PUSH C, PUSH D, POP, POP` → 꺼낸 순서는 **B, D, C**, 남은 것은 **A**
같은 동작을 큐로(삽입=ENQ, 삭제=DEQ) 하면 꺼낸 순서는 **A, B, C**, 남은 것은 **D**

**[보충] 선형 / 비선형**
- 선형: 배열, 연결 리스트, 스택, 큐, 데크
- 비선형: 트리, 그래프

## 4. 프로그래밍 언어

### 4-1. C 포인터와 배열 [원문 식 정정]

1차원 배열 `int arr[5];`에서 **배열 이름 = 첫 원소의 주소**

| 식 | 의미 | 같은 식 |
| --- | --- | --- |
| `arr + i` | i번째 원소의 **주소** | `&arr[i]` |
| `*(arr + i)` | i번째 원소의 **값** | `arr[i]` |
| `*arr + i` | 첫 원소 값에 i를 **더한 값** | `arr[0] + i` |
| `*(arr + i) + i` | i번째 원소 값에 i를 더한 값 | `arr[i] + i` |

2차원 배열 `int arr[3][4];`에서

| 식 | 같은 식 |
| --- | --- |
| `*(arr + i)` (= `arr[i]`) | i행의 시작 **주소** |
| `*(*(arr + i) + j)` | `arr[i][j]` |
| `*(*arr + i)` | `arr[0][i]` |
| `**arr` | `arr[0][0]` |

> 핵심: **`*`(괄호 안 주소)는 그 위치의 값**, 괄호 밖에서 더하면 **값에 더하기**. 괄호 위치를 꼭 확인!

**예제** [보충]
```c
#include <stdio.h>
int main() {
    int arr[5] = {10, 20, 30, 40, 50};
    int *p = arr;
    printf("%d\n", *(p + 2));      // 30  (arr[2])
    printf("%d\n", *p + 2);        // 12  (arr[0] + 2)
    printf("%d\n", *(arr + 1) + 1);// 21  (arr[1] + 1)
    p++;
    printf("%d\n", *p);            // 20  (p가 arr[1]을 가리킴)
    return 0;
}
```

### 4-2. 자바 자료형 (컬렉션)

| 클래스 | 인터페이스 | 특징 |
| --- | --- | --- |
| HashSet | Set | **중복 X**, **순서 X** |
| [보충] TreeSet | Set | 중복 X, **자동 정렬** |
| ArrayList | List | **가변 크기** 배열, 선형 리스트, **순서 O**, 인덱스 조회 빠름 |
| LinkedList | List | 각 노드가 **이전·다음 노드**를 알고 있음 → 중간 삽입·삭제 빠름 |
| HashMap | Map | **키(Key)와 값(Value)** 쌍, 키 중복 X |
| [보충] TreeMap | Map | 키 기준 **자동 정렬** |

**[보충] 자바 기본 자료형 크기**

| 정수 | 실수 | 문자·논리 |
| --- | --- | --- |
| byte 1 · short 2 · int 4 · long 8 바이트 | float 4 · double 8 바이트 | char 2 · boolean 1 바이트 |

## 5. 네트워크 — 축적 교환 방식 (댓글 보충분)

데이터를 중간 노드에 **저장(축적)했다가 전달**하는 교환 방식 (Store-and-Forward)

```
교환 방식
├─ 회선 교환 : 공간 분할 교환, 시분할 교환
└─ 축적 교환
   ├─ 메시지 교환 : 메시지 단위로 통째로 저장 후 전달
   └─ 패킷 교환
      ├─ 가상 회선 방식 : 경로를 미리 설정(연결형), 패킷이 같은 경로로 순서대로
      └─ 데이터그램 방식 : 연결 없이 패킷마다 독립적으로 경로 선택(비연결형), 순서 바뀔 수 있음
```
> 자세한 회선 교환 vs 패킷 교환 비교는 (2)편 네트워크 노트 3장 참고

## 7. 데이터베이스 기초

### 7-1. 데이터베이스 정의와 특징

| 정의 | 설명 |
| --- | --- |
| 통합된 데이터(Integrated) | **중복을 최소화**한 데이터 |
| 저장된 데이터(Stored) | 컴퓨터 **저장 매체**에 저장 |
| 운영 데이터(Operational) | 조직의 **업무** 수행에 필요한 데이터 |
| 공용 데이터(Shared) | 여러 사용자가 **공동으로** 사용 |

> 암기: **통·저·운·공**

| 특징 | 설명 [보충] |
| --- | --- |
| 실시간 접근성 | 질의에 **즉시** 응답 |
| 계속적인 변화 | 삽입·삭제·갱신으로 항상 **최신** 상태 유지 |
| 동시 공용 | 여러 사용자가 **동시에** 사용 |
| 내용에 의한 참조 | 주소가 아니라 **데이터 내용(값)** 으로 찾음 |

### 7-2. DBMS

- **[보충] DBMS 필수 기능**: **정의**(구조 정의) · **조작**(검색·갱신) · **제어**(무결성·보안·병행 제어)
- **DBMS 특징**: 무결성 · 일관성 · 회복성 · 보안성 · 효율성

**NoSQL DBMS 유형** (원문 "DBMS: 키-값 / 컬럼 기반 / 문서 저장 / 그래프")

| 유형 | 설명 [보충] | 예 |
| --- | --- | --- |
| 키-값(Key-Value) | 키와 값 쌍으로 저장, 가장 단순 | Redis, DynamoDB |
| 컬럼 기반(Column Family) | 열 단위로 묶어 저장 | Cassandra, HBase |
| 문서 저장(Document) | JSON·XML 같은 **문서** 단위 저장 | MongoDB, CouchDB |
| 그래프(Graph) | 노드와 간선으로 **관계** 저장 | Neo4j |

### 7-3. 스키마 3단계

| 스키마 | 관점 | 설명 |
| --- | --- | --- |
| **외부 스키마** | **사용자·응용 프로그래머** | 각 사용자 그룹이 보는 **일부분**의 논리적 구조 (서브 스키마, 여러 개 존재) |
| **개념 스키마** | **조직 전체** | DB **전체**를 정의, 개체 간 **관계와 제약조건**, 접근 권한·보안·**무결성 규칙** 명세 (하나만 존재) |
| **내부 스키마** | **물리적 저장 장치** | 레코드의 **물리적 구조**·저장 순서, 저장 데이터 항목의 **표현 방법** |

- **관계 스키마**: 시간에 관계없는 **정적** 성질 = 릴레이션의 **내포**(Intension) 명세 ↔ [보충] 릴레이션 **인스턴스**(외연, Extension)는 특정 시점의 튜플 집합(동적)
- [보충] **데이터 독립성**: 논리적 독립성(개념 스키마가 바뀌어도 외부 스키마 영향 X) / 물리적 독립성(내부 스키마가 바뀌어도 개념 스키마 영향 X)

### 7-4. 릴레이션 구조

| 용어 | 설명 |
| --- | --- |
| 릴레이션(Relation) | **행과 열**로 이루어진 테이블 |
| 튜플(Tuple) / 행 | 하나의 레코드. 튜플 개수 = **카디널리티(Cardinality)** |
| 속성(Attribute) / 열 | 데이터의 항목. 속성 개수 = **디그리(Degree, 차수)** |
| 식별자 | 튜플을 구분하는 속성 |
| 도메인(Domain) | 하나의 속성이 가질 수 있는 **같은 타입의 원자값 집합** |

**[보충] 예제**

| 학번 | 이름 | 학과 |
| --- | --- | --- |
| 1001 | 김철수 | 컴퓨터 |
| 1002 | 이영희 | 전자 |
| 1003 | 박민수 | 컴퓨터 |

→ 카디널리티 = **3**(행), 디그리 = **3**(열), 학과의 도메인 = {컴퓨터, 전자, …}

### 7-5. 논리 데이터 모델링

| 요소 | 설명 |
| --- | --- |
| 개체(Entity) | 관리할 **대상** (예: 학생, 과목) |
| 속성(Attribute) | 관리할 **정보 항목** (예: 학번, 이름) |
| 관계(Relationship) | 개체 간 **대응 관계** (1:1, 1:N, N:M) |

> [보충] 데이터베이스 설계 순서: 요구사항 분석 → **개념적 설계**(E-R 다이어그램) → **논리적 설계**(정규화, 테이블 변환) → **물리적 설계**(인덱스, 저장 구조) → 구현

### 7-6. 키

- 키의 조건: **유일성**(튜플을 유일하게 구분) + **최소성**(꼭 필요한 속성만)

| 키 | 설명 |
| --- | --- |
| 후보키(Candidate) | 튜플을 구별하는 기준 컬럼, **유일성 + 최소성** 만족 = 기본키 + 대체키 |
| 기본키(Primary) | 후보키 중 **선택된** 하나 (NULL·중복 불가) |
| 대체키(Alternate) | 후보키 중 **기본키가 아닌** 것 |
| 슈퍼키(Super) | **유일성만** 만족, 최소성 X (예: 학번+이름) |
| 외래키(Foreign) | **다른 릴레이션의 기본키**를 참조 → **참조 무결성** 유지 |

### 7-7. 무결성

| 무결성 | 설명 | 관련 제약조건 |
| --- | --- | --- |
| **개체 무결성** | 기본키는 **NULL 불가**, **중복 불가** | PRIMARY KEY (NOT NULL + UNIQUE) |
| **참조 무결성** | 외래키 값은 참조하는 테이블의 **기본키에 존재하는 값**이거나 NULL | FOREIGN KEY |
| **도메인(속성) 무결성** | 속성 값은 정의된 **도메인 범위** 안의 값 (NULL/NOT NULL 규칙 포함) | CHECK, DEFAULT, NOT NULL |
| 사용자 정의 무결성 | 사용자가 정한 업무 규칙 준수 | **트리거**, CHECK |

### 7-8. 이상 현상과 정규화

**이상 현상(Anomaly)**: 데이터가 불필요하게 **중복**되어 릴레이션을 조작할 때 생기는 예기치 못한 현상

| 이상 | 설명 [보충] |
| --- | --- |
| 삽입 이상 | 원치 않는 값까지 함께 넣어야 삽입 가능 |
| 삭제 이상 | 하나를 지우면 필요한 정보까지 **연쇄 삭제** |
| 갱신 이상 | 중복된 값 중 일부만 바뀌어 **불일치** 발생 |

> 암기: **삽·삭·갱**

**★ 정규화 단계**

| 단계 | 조건 |
| --- | --- |
| 제1정규형(1NF) | 모든 속성이 **원자값**(Atomic) |
| 제2정규형(2NF) | **부분 함수 종속 제거** → 기본키에 **완전 함수 종속** |
| 제3정규형(3NF) | **이행적 함수 종속 제거** (A→B, B→C 이면 A→C 인 것을 제거) |
| BCNF | **결정자이면서 후보키가 아닌 것 제거** (모든 결정자가 후보키) |
| 제4정규형(4NF) | **다치(다중값) 종속 제거** |
| 제5정규형(5NF) | **조인 종속** 제거 (후보키를 통해서만 조인 종속) |

> 암기: **"도부이결다조"** — **도**메인 원자값 · **부**분 종속 제거 · **이**행 종속 제거 · **결**정자는 후보키 · **다**치 종속 제거 · **조**인 종속 제거
> [보충] 반정규화(역정규화): 성능을 위해 일부러 중복을 허용하는 것

**[보충] 제2정규형 예**: 기본키가 (학번, 과목코드)인 `수강(학번, 과목코드, 성적, 과목명)`
→ 과목명은 과목코드만으로 결정됨 = **부분 함수 종속** → `수강(학번, 과목코드, 성적)` + `과목(과목코드, 과목명)`으로 분리

**[보충] 제3정규형 예**: `학생(학번, 학과, 학과장)`에서 학번 → 학과 → 학과장 = **이행 종속**
→ `학생(학번, 학과)` + `학과(학과, 학과장)`으로 분리

### 7-9. 관계 대수 [보충]

| 구분 | 연산자 | 기호 | 설명 |
| --- | --- | --- | --- |
| 순수 관계 연산자 | Select | **σ** (시그마) | 조건에 맞는 **행(튜플)** 선택 |
| | Project | **π** (파이) | 원하는 **열(속성)** 추출 |
| | Join | **⋈** | 공통 속성으로 두 릴레이션 결합 |
| | Division | **÷** | 나누는 릴레이션의 모든 값과 관련된 튜플 추출 |
| 일반 집합 연산자 | 합집합 / 교집합 / 차집합 / 카티션 프로덕트 | ∪ / ∩ / − / × | |

> 관계 대수 = **절차적**(어떻게), 관계 해석 = **비절차적**(무엇을)

## 8. SQL

### 8-1. SQL 분류

| 분류 | 명령어 |
| --- | --- |
| **DDL** (정의어) | CREATE, ALTER, DROP, TRUNCATE |
| **DML** (조작어) | SELECT, INSERT, UPDATE, DELETE |
| **DCL** (제어어) | GRANT, REVOKE |
| **TCL** (트랜잭션 제어) | COMMIT, ROLLBACK, SAVEPOINT |

### 8-2. DDL

```sql
-- 생성
CREATE TABLE 학생 (
    학번   CHAR(4)     PRIMARY KEY,
    이름   VARCHAR(20) NOT NULL,
    학과   VARCHAR(20) DEFAULT '컴퓨터',
    학년   INT         CHECK (학년 BETWEEN 1 AND 4),
    이메일 VARCHAR(50) UNIQUE,
    지도교수 CHAR(4)   REFERENCES 교수(교수번호)   -- FOREIGN KEY
);
CREATE INDEX idx_이름 ON 학생(이름);
CREATE VIEW 컴퓨터학생 AS SELECT 학번, 이름 FROM 학생 WHERE 학과 = '컴퓨터';

-- 변경
ALTER TABLE 학생 ADD 전화 VARCHAR(15);        -- 열 추가
ALTER TABLE 학생 MODIFY 이름 VARCHAR(30);     -- 데이터 타입 변경 (Oracle·MySQL)
ALTER TABLE 학생 DROP COLUMN 전화;            -- 열 삭제

-- 삭제
DROP TABLE 학생 CASCADE;   -- 참조하는 것까지 함께 삭제 ([보충] RESTRICT: 참조 중이면 삭제 거부)
TRUNCATE TABLE 학생;       -- 데이터만 전부 삭제, 구조는 유지
```

**[보충] DELETE vs TRUNCATE vs DROP**

| 명령 | 분류 | 삭제 대상 | 구조 | 롤백 |
| --- | --- | --- | --- | --- |
| DELETE | DML | 조건에 맞는 **행** | 유지 | 가능 |
| TRUNCATE | DDL | **모든 행** | 유지 | 불가 |
| DROP | DDL | **테이블 자체** | 삭제 | 불가 |

### 8-3. 제약조건

| 제약조건 | 설명 |
| --- | --- |
| NOT NULL | NULL 값 불가 |
| UNIQUE | 테이블 내에서 **중복 불가** |
| PRIMARY KEY | 기본키 = **NOT NULL + UNIQUE** |
| FOREIGN KEY | 다른 테이블의 기본키 참조 (**참조 무결성**) |
| CHECK | 지정한 **조건**을 만족하는 값만 입력 (예: `CHECK (성별 IN ('남','여'))`) |
| DEFAULT | 값이 없으면 **기본값** |

### 8-4. DML — SELECT

```sql
SELECT [DISTINCT] 열1, 집계함수(열2)
FROM 테이블
WHERE 조건
GROUP BY 열1
HAVING 그룹 조건
ORDER BY 열1 [ASC | DESC];
```

| 절 | 역할 |
| --- | --- |
| FROM | 대상 테이블 |
| WHERE | **행** 조건 |
| GROUP BY | 그룹으로 묶기 |
| HAVING | **그룹**에 대한 조건 (GROUP BY와 함께) |
| ORDER BY | 정렬 — ASC 오름차순(기본), DESC 내림차순 |

> [보충] **실행 순서**: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY

**WHERE 조건 연산자** [보충 포함]

| 연산자 | 예 |
| --- | --- |
| LIKE `%` | 0개 이상 문자 — `LIKE '김%'` (김으로 시작) |
| LIKE `_` | **정확히 1개** 문자 — `LIKE '김_'` (김 + 한 글자) |
| LIKE `[ ]`, `[^ ]` (SQL Server) | 1개 문자 일치 / 불일치 — `LIKE '[ABCD]%'` 첫 글자가 A·B·C·D 중 하나 |
| BETWEEN a AND b | a 이상 b 이하 |
| IN (…) | 목록 중 하나 — `학과 IN ('컴퓨터','전자')` |
| IS NULL / IS NOT NULL | NULL 비교는 `= NULL`이 아니라 `IS NULL` |

**[보충] 집계 함수**: `COUNT`, `SUM`, `AVG`, `MAX`, `MIN` — `COUNT(*)`는 NULL 포함, `COUNT(열)`은 NULL 제외

**[보충] 예제**

```sql
-- 학과별 학생 수가 2명 이상인 학과를 학생 수 내림차순으로
SELECT 학과, COUNT(*) AS 인원
FROM 학생
GROUP BY 학과
HAVING COUNT(*) >= 2
ORDER BY 인원 DESC;
```
7-4의 학생 테이블이라면 결과: `컴퓨터 | 2`

### 8-5. JOIN

| 조인 | 결과 |
| --- | --- |
| INNER JOIN | 양쪽에 **모두** 있는 행 (교집합) |
| LEFT OUTER JOIN | **왼쪽** 테이블 전부 + 오른쪽 일치 행 (없으면 NULL) |
| RIGHT OUTER JOIN | **오른쪽** 테이블 전부 + 왼쪽 일치 행 |
| FULL OUTER JOIN | **양쪽 전부** (없는 쪽은 NULL) |
| [보충] CROSS JOIN | 모든 조합 (카티션 곱, 행 수 = m × n) |
| [보충] SELF JOIN | 같은 테이블끼리 조인 |
| USING | 두 테이블에서 **같은 이름의 컬럼**을 기준으로 조인 — `JOIN 학과 USING (학과코드)` |
| [보충] NATURAL JOIN | 같은 이름의 컬럼 전부로 자동 조인 |

**[보충] 예제**: `학생(학번, 이름, 학과코드)` = {(1, 김, A), (2, 이, B), (3, 박, NULL)}, `학과(학과코드, 학과명)` = {(A, 컴퓨터), (C, 화학)}

| 조인 | 결과 행 |
| --- | --- |
| INNER | (1, 김, 컴퓨터) → **1행** |
| LEFT OUTER | (1, 김, 컴퓨터), (2, 이, NULL), (3, 박, NULL) → **3행** |
| RIGHT OUTER | (1, 김, 컴퓨터), (NULL, NULL, 화학) → **2행** |
| FULL OUTER | 위 LEFT + (NULL, NULL, 화학) → **4행** |

### 8-6. 집합 연산자

| 연산자 | 결과 |
| --- | --- |
| UNION | 합집합, **중복 제거** |
| UNION ALL | 합집합, **중복 허용** |
| INTERSECT | 교집합 (양쪽에 모두 있는 행만) |
| MINUS (표준: EXCEPT) | 차집합 (첫 쿼리에 있고 두 번째에는 **없는** 행) |

> 예) A = {1, 2, 3}, B = {2, 3, 4} → UNION {1,2,3,4} / UNION ALL {1,2,3,2,3,4} / INTERSECT {2,3} / MINUS {1}

### 8-7. DML — INSERT · UPDATE · DELETE

```sql
INSERT INTO 학생 (학번, 이름, 학과) VALUES ('1004', '최지우', '전자');
UPDATE 학생 SET 학과 = '컴퓨터' WHERE 학번 = '1004';
DELETE FROM 학생 WHERE 학번 = '1004';
```

| 명령 | 키워드 |
| --- | --- |
| INSERT | INTO, VALUES |
| UPDATE | SET, WHERE |
| DELETE | FROM, WHERE |

> 함정: UPDATE·DELETE에 **WHERE가 없으면 모든 행**이 바뀌거나 삭제된다.

### 8-8. DCL

```sql
GRANT SELECT, UPDATE ON 학생 TO user1 WITH GRANT OPTION;  -- 권한 부여 (+ 다른 사람에게 줄 권한까지)
REVOKE UPDATE ON 학생 FROM user1 CASCADE;                -- 권한 회수 (user1이 준 권한까지 연쇄 회수)
```

| 명령 | 설명 |
| --- | --- |
| GRANT | 사용 권한 **부여** (`... ON 테이블 TO 사용자`) |
| REVOKE | 사용 권한 **회수** (`... ON 테이블 FROM 사용자`) |

### 8-9. 트랜잭션 (TCL)

| 명령 | 설명 |
| --- | --- |
| COMMIT | 작업 결과를 DB에 **영구 저장** |
| ROLLBACK | 작업을 **취소**하고 이전 상태로 복구 |
| SAVEPOINT | 롤백할 **저장점** 지정 (`ROLLBACK TO 저장점`) — 원문의 "체크포인트" |

**트랜잭션 특성 ACID**

| 특성 | 설명 |
| --- | --- |
| 원자성(Atomicity) | 모두 반영되거나 **전혀** 반영되지 않음 (All or Nothing). 하나라도 오류면 **전부 롤백** |
| 일관성(Consistency) | 성공적으로 완료되면 항상 **일관성 있는** DB 상태. 고정 요소가 전후로 같음 |
| 격리성(Isolation) | 동시에 실행되는 트랜잭션이 서로 **끼어들 수 없음**. 완료 전 결과는 참조 불가 |
| 지속성(Durability) | 완료된 결과는 **영구적**으로 반영 (장애가 나도 유지) |

> 암기: **원·일·격·지** ("원일격지")

**[보충] 트랜잭션 상태**: 활동 → 부분 완료 → **완료(Commit)** / 실패 → **철회(Abort)**
