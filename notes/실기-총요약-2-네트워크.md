# 정보처리산업기사 실기 총요약 (2) — 네트워크 요약노트

> 원문: 이승우, 「정보처리산업기사 실기 총요약」 1-2과목 네트워크 기초 활용 (velog, 2024-08-18)
> 원문에서 비어 있거나 이미지로만 있던 부분(프레임 릴레이, ATM, 서킷/패킷 교환 비교, 네트워크 토폴로지 등)은 **[보충]** 표시로 채웠다.
> 원문 오류 수정:
> - 세션 계층 프로토콜 `BIOS` → **NetBIOS**
> - IEEE 802.4 `토큰 박스` → **토큰 버스**
> - IMAP(143)은 UDP가 아니라 **TCP**
> - IPv4 `10진수 12자리` → **8비트씩 4개 옥텟(0~255)을 점(.)으로 구분**한 10진수 표기
> - `U_Frame` → `U-Frame`, `Tranfer` → `Transfer`

**범위**: 1과목 응용 SW 기초 기술 활용 → **네트워크 기초 활용** (계층 구조 · 프로토콜 · 전달 방식)

## 1. 네트워크 계층 구조

### 1-1. 네트워크 분류

| 구분 | 설명 |
| --- | --- |
| LAN (근거리 통신망) | 한 건물·작은 지역을 커버. 전송 거리 짧고, 에러율 낮고, 속도 빠름 |
| [보충] MAN (도시권 통신망) | LAN과 WAN의 중간, 도시 규모 |
| WAN (광대역 통신망) | LAN보다 넓은 지역. **라우팅 알고리즘 필요**, LAN 대비 **에러율 높고 전송 지연 큼** |

| 프로토콜 | 기능 |

| L4 스위치 | 4 | TCP/UDP 포트 정보로 스위칭, HTTP·FTP 등을 구분하는 **로드 밸런싱** |
| 게이트웨이 | 3~7 (주로 응용) | **프로토콜이 서로 다른** 통신망을 연결 |

## 2. 네트워크 프로토콜

### 2-1. 프로토콜과 3요소

- **프로토콜**: 서로 다른 시스템·기기 간 데이터 교환을 원활히 하기 위한 **표준화된 통신 규약**

| 3요소 | 설명 |
| --- | --- |
| 구문(Syntax) | 데이터 **형식**, 코딩, 신호 레벨 |
| 의미(Semantics) | **제어 정보** — 조정과 에러 처리 |
| 타이밍(Timing) | **속도 조절**과 **순서** 관리 |

> 암기: **구·의·타** — "구의(區議)회 타임"

**프로토콜의 기능(특징)**

| 기능 | 설명 [보충] |
| --- | --- |
| 단편화 | 큰 데이터를 작은 블록으로 나눔 |
| 재조립 | 나뉜 블록을 원래대로 합침 |
| 캡슐화 | 데이터에 헤더(주소·제어 정보)를 붙임 |
| 연결 제어 | 연결 설정·유지·해제 |
| 오류 제어 | 오류 검출·정정 (패리티, CRC, 해밍 코드, ARQ) |
| 흐름 제어 | 수신 측 처리 능력에 맞게 전송량 조절 (정지-대기, 슬라이딩 윈도우) |
| 동기화 | 송수신 측의 타이밍을 맞춤 |
| 다중화 | 하나의 회선으로 여러 신호를 동시에 전송 |
| 주소 지정 | 송수신지 주소를 명시 |

### 2-2. IPv4

- **32비트**, 8비트씩 4개 옥텟을 **점(.)으로 구분한 10진수** (각 0~255) — 예: `192.168.0.1`
- 전송 방식: **유니캐스트, 멀티캐스트, 브로드캐스트**
- 헤더: 패킷 앞부분에 주소 등 제어 정보 — [보충] 20~60바이트(가변), 체크섬·단편화 필드 있음

**클래스 분류**

| 클래스 | 범위 (첫 옥텟) | 기본 서브넷 마스크 | 구조 | 용도 |
| --- | --- | --- | --- | --- |
| A | 0 ~ 127 | 255.0.0.0 (/8) | N.H.H.H | 대규모 (127은 루프백) |
| B | 128 ~ 191 | 255.255.0.0 (/16) | N.N.H.H | 중규모 |
| C | 192 ~ 223 | 255.255.255.0 (/24) | N.N.N.H | 소규모 |
| D | 224 ~ 239 | — | — | **멀티캐스트** |
| E | 240 ~ 255 | — | — | **연구용**(예약) |

> 첫 비트 패턴: A `0`, B `10`, C `110`, D `1110`, E `1111`

**[보충] 사설 IP 대역** (인터넷에 직접 나가지 않음, NAT로 공인 IP와 변환)
- A: `10.0.0.0 ~ 10.255.255.255`
- B: `172.16.0.0 ~ 172.31.255.255`
- C: `192.168.0.0 ~ 192.168.255.255`
- 루프백: `127.0.0.1` (자기 자신)

### 2-3. IPv6

- **128비트**, 16비트씩 8그룹, 각 그룹을 **4자리 16진수**로 표기하고 **콜론(:)으로 구분**
- 연속된 0 그룹은 `::`로 **한 번만** 축약 가능, 각 그룹의 앞자리 0도 생략 가능
  - 예: `2001:0DB8:0000:0000:0000:0000:1428:57AB` = `2001:DB8::1428:57AB`
- 특징: **주소 확장**(사실상 무한), **이동성**, **인증·보안**(IPsec 기본), [보충] 자동 주소 설정, QoS 향상
- 전송 방식: **유니캐스트, 멀티캐스트, 애니캐스트** (브로드캐스트 없음)
- 헤더: 주소가 길어져 커졌지만(**40바이트 고정**), 불필요한 필드를 없애 **단순**해짐 (체크섬 제거, 확장 헤더로 분리)

| 구분 | IPv4 | IPv6 |
| --- | --- | --- |
| 주소 길이 | 32비트 | 128비트 |
| 표기 | 10진수 4옥텟, 점 | 16진수 8그룹, 콜론 |
| 헤더 | 20~60바이트 가변 | 40바이트 고정 |
| 전송 방식 | 유니·멀티·브로드 | 유니·멀티·애니 |
| 보안 | 선택(IPsec 별도) | IPsec 기본 |

**IPv4 → IPv6 전환 방법**

| 방법 | 설명 [보충] |
| --- | --- |
| 듀얼 스택(Dual Stack) | 한 장비가 IPv4와 IPv6를 **동시에** 지원 |
| 터널링(Tunneling) | IPv6 패킷을 IPv4 패킷에 **캡슐화**해 IPv4 망을 통과 |
| 주소 변환(Header Translation) | IPv4 ↔ IPv6 헤더를 **변환**(NAT-PT) |

### 2-4. NAT · 서브넷 · DHCP

- **NAT**: **사설 IP ↔ 공인 IP** 변환 (공인 IP 절약, 내부망 은닉)
- **서브넷(Subnet)**: 클래스 단위가 아니라 **Classless**하게 네트워크를 임의로 나누는 기술 → [보충] CIDR 표기(`/26` 등)
- **DHCP**: IP를 **동적으로 할당**하고 쓰지 않는 IP를 **회수** — [보충] UDP 67(서버)·68(클라이언트)

**[보충] 서브네팅 계산 (시험 단골)**

> 문제: `200.1.1.0/24`를 **4개** 서브넷으로 똑같이 나눠라.

1. 4개 = 2² → 호스트 비트에서 **2비트**를 빌림 → `/24 + 2 = /26`
2. 서브넷 마스크: `255.255.255.192` (마지막 옥텟 `11000000` = 192)
3. 서브넷당 주소 2⁶ = **64개**, 사용 가능 호스트 64 − 2 = **62개** (네트워크 주소·브로드캐스트 주소 제외)

| 서브넷 | 네트워크 주소 | 사용 가능 범위 | 브로드캐스트 |
| --- | --- | --- | --- |
| 1 | 200.1.1.0 | .1 ~ .62 | 200.1.1.63 |
| 2 | 200.1.1.64 | .65 ~ .126 | 200.1.1.127 |
| 3 | 200.1.1.128 | .129 ~ .190 | 200.1.1.191 |
| 4 | 200.1.1.192 | .193 ~ .254 | 200.1.1.255 |

**마스크 빠른 표**

| CIDR | 마지막 옥텟 | 주소 수 | 사용 가능 호스트 |
| --- | --- | --- | --- |
| /24 | 0 | 256 | 254 |
| /25 | 128 | 128 | 126 |
| /26 | 192 | 64 | 62 |
| /27 | 224 | 32 | 30 |
| /28 | 240 | 16 | 14 |
| /29 | 248 | 8 | 6 |
| /30 | 252 | 4 | 2 |

### 2-5. 전송 방식 (캐스트)

| 방식 | 관계 | 설명 |
| --- | --- | --- |
| 유니캐스트 | 1 : 1 | 고유 주소로 식별된 **하나의** 목적지에 전송 |
| 멀티캐스트 | 1 : 그룹 | 같은 데이터를 **특정 그룹**의 수신자들에게 동시 전송 (**IGMP**) |
| 브로드캐스트 | 1 : 전체 | 같은 서브넷의 **모든** 수신자에게 전송 (IPv4만) |
| 애니캐스트 | 1 : 가장 가까운 하나 | 그룹 중 **가장 가까운** 수신자에게 전송 (IPv6) |

### 2-6. 라우팅 프로토콜 (3계층)

```
라우팅
├─ 정적(Static) : 관리자가 경로를 수동으로 지정
└─ 동적(Dynamic) : 상황에 따라 경로 자동 갱신
   ├─ 내부 라우팅 프로토콜(IGP, AS 내부) : RIP, OSPF
   └─ 외부 라우팅 프로토콜(EGP, AS 간)   : BGP
```
> [보충] **AS(Autonomous System, 자율 시스템)**: 하나의 관리 정책으로 운영되는 네트워크 집합 (예: 한 ISP)

| 구분 | RIP | OSPF | BGP |
| --- | --- | --- | --- |
| 종류 | IGP | IGP | EGP |
| 알고리즘 | **거리 벡터** (벨만-포드) | **링크 상태** (다익스트라) | [보충] 경로 벡터 |
| 경로 선택 기준 | **홉 수**(라우터 개수) | **링크 비용**(대역폭 등) | [보충] 경로 속성·정책 |
| 제한 | **최대 15홉** (16 = 도달 불가) | 홉 제한 없음 | — |
| 갱신 | **30초**마다 전체 정보 공유 | 변화가 있을 때만 갱신, **멀티캐스트** | 변화 시 갱신 |
| 포트 | **UDP 520** | [보충] IP 프로토콜 89 | **TCP 179** |
| 규모 | 소규모 | 대규모·복잡한 망 (RIP 단점 개선, [보충] Area로 계층 분할) | AS 간(인터넷 백본) |

### 2-7. 전송 계층 (4계층) — TCP / UDP

| 구분 | TCP | UDP |
| --- | --- | --- |
| 연결 | **연결형**(가상 회선) | **비연결형**(데이터그램) |
| 신뢰성 | 보장 (재전송, 순서 보장) | 보장 안 함, 순서화 안 됨 |
| 제어 | **흐름 제어, 혼잡 제어**, 오류 제어 | 없음 |
| 헤더 | [보충] 20바이트 이상, 복잡 | **8바이트, 단순** |
| 속도 | 상대적으로 느림 | 빠름, **실시간·멀티캐스트** 가능 |
| 사용 예 | HTTP, FTP, SMTP, Telnet, SSH | DNS(조회), TFTP, SNMP, DHCP, 스트리밍·VoIP |

- **TCP**: 인터넷·LAN의 프로그램 간에 **옥텟(바이트)을 안정적으로** 교환
- **가상 회선(연결형)**: 출발지–목적지 경로를 **미리 연결**해 논리적으로 고정한 뒤 통신
- **데이터그램(비연결형)**: 사전 연결 없이 **헤더에 경로 정보**를 붙여 패킷을 **개별적으로** 전달

**[보충] TCP 3-Way Handshake (연결 설정)**
```
클라이언트                 서버
    │ ── SYN ─────────────▶ │   ① 연결 요청
    │ ◀──────── SYN + ACK ── │   ② 요청 수락 + 응답
    │ ── ACK ─────────────▶ │   ③ 확인 → 연결 성립
```
- 연결 해제는 **4-Way Handshake** (FIN → ACK → FIN → ACK)

### 2-8. 응용 계층 (7계층) 포트 번호

| 프로토콜 | 포트 | TCP/UDP | 설명 |
| --- | --- | --- | --- |
| FTP | **20**(데이터), **21**(제어) | TCP | 서버–클라이언트 파일 전송 |
| SSH | **22** | TCP | 암호화된 원격 접속(보안) |
| Telnet | **23** | TCP | 원격 접속(평문, 보안 취약) |
| SMTP | **25** | TCP | 이메일 **보내기** |
| DNS | **53** | TCP/UDP | **도메인 이름 → IP** 변환 |
| [보충] DHCP | 67 / 68 | UDP | IP 자동 할당 |
| TFTP | **69** | UDP | 인증 없는 간단한 파일 전송 |
| HTTP | **80** | TCP | 웹 데이터 송수신 |
| POP3 | **110** | TCP | 이메일 **가져오기**(서버에서 내려받고 삭제) |
| [보충] NTP | 123 | UDP | 시간 동기화 |
| IMAP | **143** | TCP | 이메일 **가져오기**(서버에 보관한 채 동기화) |
| SNMP | **161** ([보충] 트랩 162) | UDP | 네트워크 장치 정보 수집·관리 |
| [보충] HTTPS | 443 | TCP | HTTP + SSL/TLS 암호화 |

> 암기: 메일 **보내기 = SMTP(25)**, **받기 = POP3(110) / IMAP(143)**
> 숫자 순서대로: 20·21 FTP → 22 SSH → 23 Telnet → 25 SMTP → 53 DNS → 69 TFTP → 80 HTTP → 110 POP3 → 143 IMAP → 161 SNMP → 443 HTTPS

## 3. 네트워크 전달 방식

### 3-1. 패킷 교환 방식

- 데이터를 **패킷** 단위로 나눠 전송, **전송하는 동안만** 네트워크 자원 사용 (예: 이메일, 메시지)
- [보충] 방식: **가상 회선**(연결형, 경로 고정) / **데이터그램**(비연결형, 패킷마다 경로 다름)

**X.25**
- 두 단말이 **패킷 교환망**을 통해 패킷을 전달하기 위한 프로토콜
- 패킷 교환망에서 **DTE**(단말장치)와 **DCE**(회선종단장치) 간 인터페이스 제공
- 특징: 고정된 대역폭, 패킷 사용, **OSI 1~3계층** 담당, 송수신 신뢰성(오류 제어 강함), 그 대신 **성능 저하**(오버헤드)

**[보충] 프레임 릴레이 (Frame Relay)**
- X.25를 개선한 고속 패킷 교환 방식, 데이터링크 계층(2계층)에서 **프레임** 단위로 전송
- 오류 제어·흐름 제어를 단말에 맡기고 망에서는 **최소화** → X.25보다 빠름
- 회선 품질이 좋은 환경 전제, 가변 길이 프레임

**[보충] ATM (Asynchronous Transfer Mode, 비동기 전송 모드)**
- **53바이트 고정 길이 셀**(헤더 5 + 페이로드 48) 단위로 전송하는 고속 교환 방식
- 패킷 교환 + 회선 교환의 장점 결합, 음성·영상·데이터를 함께 처리
- B-ISDN의 핵심 전송 기술, 연결형(가상 회선), QoS 보장

| 구분 | X.25 | 프레임 릴레이 | ATM |
| --- | --- | --- | --- |
| 전송 단위 | 패킷(가변) | 프레임(가변) | **셀(53바이트 고정)** |
| 계층 | 1~3 | 1~2 | 1~2 |
| 오류 제어 | 망에서 강하게 | 최소화 | 최소화 |
| 속도 | 느림 | 빠름 | 매우 빠름 |

### 3-2. 서킷(회선) 교환 방식

- 통신 동안 네트워크 자원(회선)을 **특정 사용자가 독점** (예: 전화, 영상·비디오)
- 특징: **전송 보장**, 데이터 전송 전 **서킷 확보 작업**(호 설정) 필요, 연결 후 접속 시간(전송 지연) 빠름, 송수신 측 모두 **준비 완료**돼야 통신 가능

### 3-3. [보충] 서킷 교환 vs 패킷 교환 (원문 이미지 대체)

| 구분 | 서킷(회선) 교환 | 패킷 교환 |
| --- | --- | --- |
| 자원 사용 | 연결 동안 회선 **독점** | 전송할 때만 **공유** |
| 연결 설정 | 필요(호 설정) | 가상 회선은 필요, 데이터그램은 불필요 |
| 전송 지연 | 연결 후 **일정·적음** | 노드마다 저장-전달로 **가변** |
| 대역폭 효율 | 낮음 (안 쓸 때도 점유) | 높음 |
| 속도·코드 변환 | 불가 | 가능 |
| 적합 | **실시간** 음성·영상 | 이메일·파일 등 **데이터** 통신 |

### 3-4. IEEE 802 (LAN 표준)

| 표준 | 내용 |
| --- | --- |
| 802.1 | [보충] 전체 구성, 브리지, 네트워크 관리 |
| 802.2 | [보충] LLC (논리 링크 제어) |
| **802.3** | **이더넷(Ethernet)** — **CSMA/CD** |
| 802.4 | **토큰 버스** |
| 802.5 | **토큰 링** |
| **802.11** | **무선 LAN(Wi-Fi)** — [보충] **CSMA/CA** |
| 802.15 | [보충] 무선 PAN (블루투스, 지그비) |

**[보충] CSMA/CD vs CSMA/CA**
- **CSMA/CD**(Collision **Detection**): 유선 이더넷. 회선이 비었는지 확인 후 전송, **충돌을 감지**하면 중단하고 임의 시간 뒤 재전송
- **CSMA/CA**(Collision **Avoidance**): 무선 LAN. 무선은 충돌 감지가 어려워 전송 전 **대기·예약(RTS/CTS)** 으로 충돌을 **회피**

### 3-5. HDLC

- **비트 위주**의 데이터링크 제어 프로토콜, 동기식 전송

| 프레임 | 용도 |
| --- | --- |
| I-Frame (정보) | **사용자 데이터** 전송 |
| S-Frame (감독) | **오류·흐름 제어** (RR, RNR, REJ, SREJ) |
| U-Frame (비번호) | 링크 **설정·해제** 등 제어 |

- [보충] 프레임 구조: 플래그(01111110) · 주소 · 제어 · 정보 · FCS · 플래그
- [보충] 동작 모드: **NRM**(정규 응답, 주국이 허가해야 종국 전송) · **ARM**(비동기 응답, 종국이 허가 없이 전송) · **ABM**(비동기 균형, 혼합국끼리 대등)

### 3-6. 네트워크 기술

| 기술 | 설명 |
| --- | --- |
| 애드 혹 네트워크(Ad-hoc) | 재난 현장처럼 고정 유선망을 구축할 수 없는 곳에서 **모바일 호스트만으로** 구성한 네트워크. 단기간 사용하거나 유선망 구성이 어려운 경우에 적합 (기지국·AP 없음) |
| NFC | **고주파(13.56MHz)** 를 이용한 **10cm 이내** 근거리 무선 통신 (교통카드, 모바일 결제) |
| [보충] 메시 네트워크 | 대규모 디바이스를 위한 다대다 그물형 무선망 (사물통신, 차세대 이동통신) |
| [보충] WPAN | 블루투스, 지그비(저전력·저속), UWB 등 개인 영역 무선망 |

### 3-7. [보충] 네트워크 토폴로지 (구축 형태)

| 형태 | 구조 | 장점 | 단점 |
| --- | --- | --- | --- |
| 성형(Star) | 중앙 노드에 모든 단말이 1:1 연결 | 관리 쉬움, 고장 발견 쉬움 | **중앙 노드 고장 시 전체 마비** |
| 링형(Ring) | 이웃 노드끼리 원형 연결 | 양방향 전송 가능, 공평 | 한 노드 고장이 전체에 영향, 노드 추가 어려움 |
| 버스형(Bus) | 하나의 공통 회선에 여러 노드 연결 | 구조 단순, 노드 추가 쉬움, 한 노드 고장이 전체에 영향 없음 | 통신량 많으면 충돌·지연, 회선 고장 시 전체 마비 |
| 계층형(Tree) | 중앙 노드 아래 트리 모양 분산 | 분산 처리에 적합 | 상위 노드 고장 시 하위 전체 영향 |
| 망형(Mesh) | 모든 노드가 서로 연결 | 신뢰성·장애 극복 최고 | 회선 수 많아 비용 큼 |

> 망형 회선 수 공식: 노드 n개 → **n(n−1)/2**, 포트 수 = **n−1** (노드당)
> 예) 노드 5개 → 5×4/2 = **10개** 회선
